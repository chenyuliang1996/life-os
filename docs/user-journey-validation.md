# Life OS 真实用户动线验证

## 1. 验证方式

本轮不是只看接口返回，而是用真实浏览器分别模拟不同身份进入服务，观察：

- 首屏是否干净
- ToC 和 ToB 是否真的分层
- 用户数据是否串号
- 护栏与权限说明是否可理解
- 运营视图是否会污染业务数据

## 2. 验证身份

- `urban-traveler`
  - 目标：验证旅行与确认流
- `habit-builder`
  - 目标：验证习惯保护和用户隔离
- `guest-explorer`
  - 目标：验证受限身份与安全护栏
- `ops-reviewer`
  - 目标：验证运营视角、全局审计和系统状态

## 3. 发现的问题

### 3.1 默认通用账号首屏过脏

问题表现：

- 默认 `lifeos-user` 会带出大量历史计划
- 待确认项看起来像无限累积
- 新用户首次进入体验不可信

修复方式：

- 中英文页面默认改为干净 persona
- 前端保持 persona 选中状态
- 用户手动切换身份时，自动刷新用户作用域数据

### 3.2 ToB 模块探针会写业务数据

问题表现：

- 刷新运营台会生成新计划和确认项
- 审批积压被探针自己放大
- 这会误导容量和可靠性判断

修复方式：

- 把 `executeProbe()` 全部改成只读摘要
- 不再通过 probe 触发编排、记忆写入或确认流

### 3.3 中文界面暴露过多工程态英文

问题表现：

- 运行时、护栏、RAG、连接器等卡片中有大量英文摘要
- 对真实用户和运营都不够友好

修复方式：

- 前端对运行时、护栏、架构、RAG、连接器做本地化格式化
- 对 persona、信任级别、权限原因做更贴近产品语义的展示

### 3.4 ToB 审计视角过窄

问题表现：

- `ops-reviewer` 只能看到自己的审计，无法观察全局运行态

修复方式：

- 运营视角下审计接口默认切为全局读取
- 普通用户仍保持 `userId` 作用域

## 4. 当前用户体验结果

### ToC

- 首屏默认进入干净 persona
- persona 切换后，计划、确认项、画像和知识都能按身份收口
- 共享知识和个人知识来源可区分
- 护栏能明确告诉用户自己是否可用实时搜索和远程专家

### ToB

- 运行时、容量、RAG、连接器和安全控制面都能直接查看
- 模块探针不再写库
- 运营身份可看到全局审计流水

## 5. 后续仍可继续增强

- 把 persona 与真实鉴权身份打通
- 为运营台增加审计筛选和时间范围
- 把共享知识与个人知识拆成更明确的视图
- 把审批积压拆成全局与当前身份两个口径
